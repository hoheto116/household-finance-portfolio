# AIコーディングツールを活用した開発プロセス

## 開発対象

家族で実際に使う家計管理・月次精算アプリ。従来の「明細収集→Excel転記→計算→振込額確認」を、LINEからの入力とWeb上の計算確認に置き換えた。

## 役割分担

| 担当 | 内容 |
| --- | --- |
| 開発者本人 | 家庭内の業務課題整理、要件・計算ルールの判断、設計方針の決定、Codexへの指示、実機での受入確認、改善指示 |
| Codex | 指示に基づくコードの生成・修正・検証作業の支援 |
| 実運用 | 家族によるLINE登録・通知・Web計算の利用 |

AIが自動的に要件を決めて完成させたわけではなく、**人間が仕様を判断し、AIの実装結果を検証する**進め方を採用した。

## 具体例：月次計算の実装

**課題**：Excelで運用していた計算を自動化する際、円未満の丸め方や参照項目を曖昧にすると、計算結果がずれる。

**方針**：JavaScriptの文字列式を実行せず、JSONの式ツリーを検証して評価する。計算途中はBigIntによる有理数を使い、丸めは `floor` / `ceil` / `round` を明示する。循環参照、無効な参照、式の複雑さも制限する。

**成果物**：[計算エンジン](../showcase/calculation-engine.ts)、[計算式表示](../showcase/Formula.tsx)。

**検証観点**：Excelとの照合、円未満の切り捨て、循環参照、未入力と0円の区別、確定済み月の再計算防止。

## 具体例：LINEからの登録と通知

**課題**：家族が入力した金額と証跡画像を扱うため、本人確認・重複登録防止・通知画像のアクセス制御が必要。

**方針**：Webhookは生のリクエストに対して署名を検証。金額と画像を下書きとして受け取り、確認操作後に登録する。通知用画像は非公開R2に保持し、期限付きのトークンURLを使用する。

**成果物**：[LINE署名・入力処理](../showcase/line-domain.ts)、[LINE API通信](../showcase/line-client.ts)、[通知画像配信](../showcase/line-notification-images.ts)。

**検証観点**：不正署名、未登録ユーザー、再送、画像形式・サイズ、期限切れ、同時入力、月次確定後の編集拒否。

## 動作確認と限界

実運用ではLINE登録、家族への通知、証跡画像共有、Web上の計算内訳表示を確認した。従来の月次作業負担は体感で約80%軽減したが、計測値ではない。

本資料は元プロジェクトの実装・仕様記録を要約したもので、**Codexとの実際の会話ログや個別プロンプトを再現したものではない**。AIによる生成箇所の割合も計測していない。
